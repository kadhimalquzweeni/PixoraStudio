**Supported decoder subset:** frame-coded, 8-bit, non-separate 4:2:0 and 4:2:2 CAVLC and CABAC pictures, subject to the explicit syntax/tool limitations recorded below and in [the CABAC validation plan](H264_CABAC_VALIDATION.md).

**Still unsupported:** FMO, field/MBAFF/interlaced decoding, separate colour planes, 4:4:4, high bit depth, SP/SI slice reconstruction, and in-band SPS/PPS updates. CABAC implementation coverage is not yet equivalent to conformance certification: broader independently decoded real-stream comparisons across varied CABAC tools and picture structures remain outstanding. Real-stream conformance and independently verified reference-output comparisons remain outstanding. The output scheduler orders decoded frame surfaces. The deblocking filter is implemented for the supported frame-coded 8-bit 4:2:0/4:2:2 subset, and reference insertion/presentation now require complete metadata and filtered samples; comprehensive real-stream conformance validation remains outstanding. MP4 AVC samples now flow through avcC parsing, access-unit dispatch, managed I/P/B slice reconstruction, DPB reference insertion and POC-reordered output with the originating sample timestamps preserved. Field pairing, streaming recovery and wiring managed decoded frames into the WPF playback surface remain outstanding. The media-engine seek API now starts at the preceding MP4 sync sample and decodes forward while retaining exact DTS/PTS/duration metadata.

The detailed bullets below record implementation history; where they say a feature remains outstanding, this current-status section takes precedence.

PixoraStudio is implementing a managed H.264/AVC decoder in `PixoraStudio.MediaEngine`. The target is native decoding without FFmpeg or LibVLC in the decoding path. Those tools may be used externally to create reference test streams, but are not runtime decoder dependencies.

## Decoder scope and support policy

The roadmap targets a standards-based decoder with explicit profile/tool capability checks. H.264 is not a single fixed bitstream format: profiles, chroma formats, bit depths, entropy modes, interlace modes and optional tools vary substantially. A stream must be rejected with a clear unsupported-feature error whenever its syntax or decoding tools are not implemented. It must never be silently rendered as if correctly decoded.

## Implementation stages

1. **Bitstream foundation** — Annex B and MP4 length-prefixed NAL framing, EBSP/RBSP conversion, bit reading and Exp-Golomb primitives. Initial SPS/PPS parsing is in place.
2. **Parameter sets and picture syntax** — complete SPS/PPS including VUI/HRD, slice-group syntax, slice headers, picture-order-count derivation and reference-list modification.
3. **Baseline profile reconstruction** — CAVLC residual parsing, inverse scans/transforms/dequantisation, intra prediction, macroblock reconstruction and decoded-picture-buffer management.
4. **Inter prediction** — P/B slice syntax, reference picture lists, motion-vector prediction, sub-pixel interpolation, weighted prediction and motion compensation.
5. **Additional profiles/tools** — CABAC, Main/High profile transforms and prediction tools, field coding and supported chroma/bit-depth variants. Each tool is gated by conformance tests.
6. **Output and container integration** — cropped YUV picture surfaces, colour conversion, MP4 sample/decode-order scheduling, POC reordering, seeking and synchronisation with the existing AAC playback path.
7. **Compatibility and hardening** — real-stream test corpus, malformed/truncated bitstreams, resource limits, cancellation and regression/performance tests.

Unidirectional partitions use their selected list prediction; bi-predicted partitions use default averaging, explicit weighted bi-prediction (weighted_bipred_idc 1), or POC-derived implicit weighting (weighted_bipred_idc 2). A B prediction assembler validates non-overlapping, complete luma/chroma macroblock coverage before residual reconstruction. Direct partitions are still rejected pending spatial/temporal direct derivation; this is a prediction stage, not yet a complete B macroblock or B-slice decoder.

- Frame-coded spatial direct motion-vector derivation is now available for B_Direct_16x16 and direct B_8x8 sub-macroblocks. It derives each list's reference index from the available spatial neighbours, applies the direct-zero condition, predicts both list vectors independently, and records them in decoding order. The SPS direct_8x8_inference_flag controls whether each direct region is represented as one 8x8 vector or four 4x4 vectors. Temporal direct prediction still requires collocated-picture motion metadata and is not implemented.

- A B inter macroblock reconstruction orchestrator now connects frame-coded B prediction syntax, independent list-0/list-1 spatial motion-vector reconstruction, spatial direct derivation, both reference lists, motion compensation, default/explicit/implicit bi-prediction, inter coded-block-pattern/QP syntax, CAVLC residual parsing and the shared inter residual reconstruction path. B_Skip has a separate no-residual prediction-and-commit path using spatial direct mode. Temporal direct remains explicitly unsupported until collocated-picture motion metadata is retained.

- Frame-coded CAVLC B-slice traversal is now integrated. The decoder parses B slice headers, constructs both active reference lists from the DPB with independent list modifications, expands `mb_skip_run` into B_Skip reconstruction, decodes B inter macroblocks through the complete prediction/residual pipeline, and routes B-slice I_NxN, I_16x16 and I_PCM macroblocks through the existing intra/PCM reconstruction paths. It maintains list-specific motion-vector state and picture-relative luma/Cb/Cr CAVLC contexts across slices, updates QPY, and validates RBSP trailing bits. CABAC, FMO, field/MBAFF, separate planes, unsupported chroma/bit-depth, and temporal direct prediction remain rejected.

- P-slice traversal now reconstructs the intra-coded macroblock types permitted inside P slices instead of rejecting them. I_NxN (Intra4x4/Intra8x8), I_16x16 and I_PCM use the existing intra/PCM syntax, residual and reconstruction paths; intra regions are marked unavailable in list-0 motion-vector state, and PCM seeds CAVLC neighbour TotalCoeff contexts. P-slice result metadata now distinguishes inter reconstruction results from intra macroblock addresses while reporting the total decoded macroblock count.

- Inter `transform_size_8x8_flag` is now retained instead of rejected. The CAVLC inter residual reader decodes each coded 8x8 luma transform as four ordered 4x4 coefficient lists and interleaves them into the 64-level scan sequence; uncoded 8x8 regions still update all four neighbour TotalCoeff entries. Inter residual reconstruction applies the 8x8 inverse quantiser/transform with the inter 8x8 scaling matrix and writes the reconstructed block into its macroblock region. Both P and B macroblock orchestrators now pass the parsed transform flag through this path.

- A decoded-picture output scheduler now connects the stateful POC calculator to the presentation-order queue. It reads `max_num_reorder_frames` from VUI bitstream restrictions, validates it against `max_dec_frame_buffering`, accepts an explicit fallback when VUI does not signal the restriction, and applies IDR `no_output_of_prior_pics_flag` by flushing or discarding prior pending pictures before queuing the IDR frame. The queue still operates on decoded frame surfaces; MP4 sample timestamps, field pairing and end-to-end playback integration remain container responsibilities.

- Temporal direct motion-vector distance scaling is implemented, including `td`/`tb` clipping, distance-scale clipping, long-term collocated-reference handling, zero-vector fallback when the collocated reference is unavailable, and L0/L1 vector derivation. The B motion-vector reconstructor, B macroblock reconstruction (including B_Skip), and B-slice traversal now accept a region-based collocated-metadata provider. Automatic collocated motion-field persistence in the DPB is still required before the playback pipeline can provide this callback without external assistance.

- The DPB can now retain each reference picture's list-0/list-1 motion-vector grids and the reference lists used when that picture was decoded. `CreateTemporalDirectMotionField` restores that metadata, and B-slice traversal automatically selects `RefPicList1[0]` as the collocated picture when temporal direct is signalled. The explicit callback remains available for externally managed or custom collocated metadata. MMCO conversion preserves the retained motion metadata.

- P- and B-slice decode results now expose the exact ordered reference-picture metadata used by the slice. This lets the caller persist the current picture's list-0/list-1 motion grids together with the matching reference lists when inserting it into the DPB, so later B pictures can resolve temporal direct prediction without a separately maintained lookup table.

Example DPB persistence after a decoded B picture:

```csharp
dpb.StoreDecodedPicture(
    decodedSurface, currentReferencePicture, isReferencePicture,
    maxNumRefFrames, currentFrameNum, maxFrameNum,
    sliceHeader.DecodedReferenceMarking,
    motionVectorStateL0: motionStateL0,
    motionVectorStateL1: motionStateL1,
    referenceList0: decodeResult.ReferencePictureLists!.List0,
    referenceList1: decodeResult.ReferencePictureLists.List1);
```

For a P picture, persist the P decoder's motion state as list 0, use an empty list-1 motion state, and pass `decodeResult.ReferenceList0` plus an empty list 1. This retains the exact reference metadata needed if that picture is selected as the collocated picture by a later B slice.

- POC conformance review tightened type 0/1/2 state handling: MMCO 5 now normalizes the current picture's top/bottom field order counts to a new POC epoch, type 1/2 frame-number history advances across non-reference pictures, type 0 reference POC history remains reference-only, and frame/POC syntax is checked against SPS bit widths. Regression tests cover MMCO 5 and frame-number wrap across non-reference pictures.

- Reference-picture insertion and presentation output now reject partially reconstructed surfaces. The surface exposes an `IsComplete` marker, DPB insertion snapshots motion grids/reference lists defensively, and output scheduling validates POC syntax before mutating the pending output queue. Tests cover incomplete surfaces, immutable DPB metadata snapshots, and malformed IDR input.

- MMCO 5 POC state now retains the current picture's syntax `frame_num` while resetting `FrameNumOffset` for the following picture, as required by the POC type 1/2 derivation. Regression coverage checks wraparound after MMCO 5 as well as after non-reference pictures.

- Direct-mode conformance review now separates spatial `colZeroFlag` from temporal scaling. Spatial direct applies `colZeroFlag` only when the derived list reference index is zero and preserves unused prediction directions as null. Temporal direct derives `tb` and `td` relative to the mapped current list-0 reference picture (`pic0`), maps the collocated reference to the lowest matching active RefPicList0 index, and observes any current short-/long-term re-marking. Regression tests cover non-zero list-0 mapping and one-list-only spatial direct prediction.

- Output-order handling now performs the prior-picture bumping required when MMCO 5 starts a new POC epoch, before queuing the normalized current picture. POC validation also enforces IDR frame_num/POC constraints and rejects MMCO 5 on non-reference or IDR pictures.

- The output scheduler now exposes a pre-reconstruction POC calculation path and an overload that enqueues the same precomputed POC after the surface is complete. This allows temporal direct prediction to use the current picture POC during B-slice reconstruction without advancing the POC state a second time when the picture is finally queued.
\n- The H.264 in-loop deblocking filter is a remaining correctness milestone. The current `H264DecodedPictureSurface` does not yet retain all per-macroblock QP, coded-block, motion/reference and slice deblocking metadata required to derive boundary strengths and thresholds. Do not treat the current reconstructed surfaces as fully conformant final output until the filter and metadata path are integrated.

- The sample-level deblocking kernel milestone is in place: H.264 alpha/beta/tC0 tables, weak filtering for bS 1–3, strong filtering for bS 4, and 8-bit luma/chroma-style edge handling. These are tested as isolated edge primitives only; the decoder still does not derive per-edge boundary strengths, retain all required macroblock metadata, or run the filter over a completed picture.

- A caller can now attach defensive, validated per-macroblock deblocking metadata to a completed surface and run `H264DeblockingPictureFilter.Apply`. The picture pass handles 4:2:0/4:2:2 luma/chroma edges, `disable_deblocking_filter_idc` slice-boundary rules, and suppression of internal luma 4x4 edges inside 8x8 transforms. The filter is a one-time terminal surface operation. Automatic metadata production from I/P/B reconstruction remains the next integration task.

- When complete deblocking metadata is attached, both DPB reference insertion and the decoded-picture output scheduler automatically run the picture filter before retaining or presenting the surface. If metadata is absent, the current decoder still permits the pre-deblocking surface; automatic metadata generation remains outstanding, so full-stream conformance is not yet claimed.

- I-slice, P-slice and B-slice intra/PCM reconstruction attaches deblocking metadata using the current QP, mapped chroma QPs, transform mode and slice-level filter controls. P inter macroblocks and P_Skip now also attach per-4x4 list-0 reference/motion metadata plus luma/chroma coded-coefficient flags whenever the caller supplies the matching ordered `H264ReferencePicture` list; the DPB-backed P-slice overload supplies this automatically. B inter macroblocks and B_Skip attach per-4x4 list-0/list-1 reference/motion metadata and residual flags from the slice's exact ordered reference lists. Tests now assert that P inter, P_Skip, B inter and B_Skip paths populate this metadata. The lower-level P macroblock API still permits omitting reference metadata for callers that only have decoded surfaces; in that case pixels reconstruct, but the surface intentionally remains ineligible for automatic picture deblocking until metadata is attached.
