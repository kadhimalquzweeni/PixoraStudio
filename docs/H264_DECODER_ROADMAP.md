# H.264 / AVC decoder roadmap

PixoraStudio is implementing a managed H.264/AVC decoder in `PixoraStudio.MediaEngine`. The target is native decoding without FFmpeg or LibVLC in the decoding path. Those tools may be used externally to create reference test streams, but are not runtime decoder dependencies.

## Decoder scope and support policy

The roadmap targets a standards-based decoder with explicit profile/tool capability checks. H.264 is not a single fixed bitstream format: profiles, chroma formats, bit depths, entropy modes, interlace modes and optional tools vary substantially. A stream must be rejected with a clear unsupported-feature error whenever its syntax or decoding tools are not implemented. It must never be silently rendered as if correctly decoded.

## Implementation stages

1. **Bitstream foundation** — Annex B and MP4 length-prefixed NAL framing, EBSP/RBSP conversion, bit reading and Exp-Golomb primitives. Initial SPS/PPS parsing is in place.
2. **Parameter sets and picture syntax** — complete SPS/PPS including VUI/HRD, slice-group syntax, slice headers, picture-order-count derivation and reference-list modification.
3. **Baseline profile reconstruction** — CAVLC residual parsing, inverse scans/transforms/dequantisation, intra prediction, macroblock reconstruction and decoded-picture-buffer management.
4. **Inter prediction** — P/B slice syntax, reference picture lists, motion-vector prediction, sub-pixel interpolation, weighted prediction and motion compensation.
5. **Additional profiles/tools** — CABAC, Main/High profile transforms and prediction tools, field coding and supported chroma/bit-depth variants. Each tool is gated by conformance tests.
6. **Output and container integration** — cropped YUV picture surfaces, colour conversion, MP4 sample/decode-order scheduling, POC reordering, seeking and synchronisation with the existing AAC playback path.
7. **Compatibility and hardening** — real-stream test corpus, malformed/truncated bitstreams, resource limits, cancellation and regression/performance tests.

## Current implementation status

- NAL framing, EBSP-to-RBSP conversion, bit reader and initial SPS/PPS readers are implemented.
- SPS parsing now reads VUI aspect ratio, overscan, video signal/colour description, chroma location, timing, NAL/VCL HRD, picture-structure and bitstream-restriction metadata.
- VUI/HRD parsing is covered by focused synthetic unit tests.
- PPS parsing now covers reference defaults, weighted prediction, QP offsets, deblocking/constrained-intra/redundant-picture flags, all FMO map syntax types (0–6), and the optional transform/scaling-matrix extension. The SPS is accepted as an optional context when PPS scaling-list count depends on chroma format.
- Slice-header parsing is implemented for ordinary non-IDR and IDR slice NAL units, covering I/P/B/SP/SI slice types, frame/field syntax, POC types 0/1/2, reference-count overrides, reference-list modifications, weighted prediction tables, decoded-reference marking/MMCO, CABAC initialisation syntax, QP/deblocking syntax and FMO slice-group change cycles.
- A stateful POC calculator now derives top-field, bottom-field and picture order counts for POC types 0, 1 and 2, including LSB wraparound, frame-number wraparound, reference/non-reference pictures, field pictures, IDR resets and MMCO 5 state resets. It must be called once per primary coded picture.
- SPS now retains the frame-number gap flag, MBAFF flag and POC type 1 offset-cycle values needed by picture-order derivation.
- Focused synthetic slice-header tests cover IDR/I, P with list modification and MMCO, B weighted prediction, POC type 1 field pictures, SP/CABAC and FMO cycle parsing.
- CAVLC VLC tables are implemented for context-selected coeff_token, separate 4:2:0 and 4:2:2 chroma-DC coeff_token, total_zeros and run_before. Residual-block decoding assembles trailing-one signs, coefficient levels (including level-prefix escape handling), total_zeros and run_before into forward scan-order coefficient arrays. 4x4 zigzag/field and 8x8 zigzag/field scan conversion are implemented. The 4x4 and 8x8 inverse integer transforms and 2x2 chroma-DC Hadamard transform are implemented with focused tests. A 4x4 inverse quantiser now applies the three H.264 position classes, QP quotient/remainder scaling and raster-order scaling lists; slice luma QP derivation includes the SPS bit-depth offset and range checks. SPS/PPS scaling-list syntax is retained, including use-default markers, and the scaling-matrix resolver applies normative defaults, list inheritance, SPS-to-PPS fallback and raster-order conversion for both 4x4 and 8x8 matrices. The 8x8 resolver supports the two lists used by 4:2:0/4:2:2 and all six lists for 4:4:4. The 8x8 inverse quantiser applies the six normative coefficient position classes, QP quotient/remainder scaling and resolved raster-order matrices. Both quantisers can consume effective SPS/PPS matrices directly. I_16x16, Intra4x4 and Intra8x8 I_NxN reconstruction and I_PCM parsing are integrated for frame-only 8-bit 4:2:0/4:2:2 macroblocks; a CAVLC I-slice decoder now traverses and reconstructs these macroblocks from slice NAL units.
- Slice-aware CAVLC neighbour-context state now tracks decoded 4x4 block TotalCoeff values, derives nC from available left/top neighbours using the normative rounded average, and treats picture edges, undecoded neighbours and neighbours in another slice as unavailable. Its wrapper decodes ordinary 15/16-coefficient blocks and records TotalCoeff for later blocks; chroma DC blocks continue to use their dedicated VLC context. Focused tests cover neighbour availability, averaging, slice boundaries, reset, validation and residual-reader integration. The caller must supply picture-relative 4x4 block coordinates in decoding order. A CAVLC I-slice traversal layer now continues from the parsed slice header, decodes I_NxN/I_16x16/I_PCM macroblocks in raster order, maintains QP and luma/chroma CAVLC neighbour state, commits decoded planes and validates RBSP trailing bits. It currently rejects P/B/SP/SI slices, CABAC, FMO, field coding, separate-colour-plane and unsupported chroma/bit-depth configurations.
- Spatial list-0 motion-vector prediction is implemented for frame-coded partitions. It accepts left/above/above-right candidates (with above-left fallback), matches reference indices, applies the 16x8 and 8x16 preferred-neighbour rules, and otherwise derives the component-wise median with unavailable candidates represented by zero. Picture-relative motion-vector state now stores inter partitions on a 4x4-luma-block grid, derives A/B/C/D candidates from decoded regions, and enforces picture bounds, decode availability and slice boundaries. The state integrates predictor selection with signed MVD addition and immediately publishes each reconstructed partition so later partitions can use it in decoding order. Motion-vector components are clipped to the normative signed 16-bit quarter-luma-sample range after predictor-plus-MVD reconstruction. Frame-coded P-slice RefPicList0 construction now orders short-term references by descending PicNum (including frame_num wrap) followed by long-term references in ascending LongTermFrameIndex order, and applies idc 0/1/2 list modifications with PicNum wrap, insertion and duplicate removal. This stage consumes an explicit decoded-reference metadata set; decoded-picture-buffer marking/MMCO lifecycle and field-picture list construction remain outstanding. Weighted prediction and complete inter-macroblock reconstruction remain outstanding.
- P-slice inter-macroblock syntax foundations parse the five list-0 inter macroblock types (P_L0_16x16, P_L0_L0_16x8, P_L0_L0_8x16, P_8x8 and P_8x8ref0), including active-reference index validation, all four sub-macroblock shapes, and signed horizontal/vertical motion-vector differences in syntax order. The syntax reader and picture-relative motion-vector state are implemented as separate tested stages; full P-slice traversal, decoded-picture-buffer integration, residual integration and completed inter-macroblock reconstruction remain outstanding.
- An initial I/P macroblock-header prefix reader now decodes I_NxN, I_16x16 and I_PCM type codes, classifies P-slice inter/intra macroblock types, and reads P-slice `mb_skip_run` values with picture-boundary checks. Intra syntax parsing now reads the sixteen 4x4 or four 8x8 `prev_intra*_pred_mode_flag` / `rem_intra*_pred_mode` entries, applies normative remainder-mode remapping when a neighbour-derived predicted mode is supplied, parses chroma prediction mode, maps intra coded-block-pattern values through Table 9-4, and reads `mb_qp_delta` when required (including the I_16x16 exception). The syntax reader supports monochrome, 4:2:0, 4:2:2 and separate-colour-plane handling at this layer. Neighbour-derived Intra4x4 prediction-mode lookup is now implemented as picture-relative state: it applies the DC-mode fallback for unavailable neighbours, takes the minimum of available left/top modes, respects slice boundaries and resolves/stores parsed prev-mode/remainder entries. Slice-aware neighbour-derived prediction-mode contexts now cover both Intra4x4 and Intra8x8 luma blocks. Each context uses picture-relative block coordinates, applies DC mode 2 whenever either neighbour is unavailable, takes the minimum when both are available, respects slice boundaries and resolves/stores parsed prev-mode/remainder entries. A macroblock-level residual payload reader consumes frame-only I_NxN 4x4 luma residual blocks and the four interleaved 4x4 CAVLC coefficient lists for each I_NxN 8x8 luma block, and I_16x16 luma DC plus optional 15-coefficient AC blocks. It follows the H.264 4x4 macroblock block-scan order, checks coded-block-pattern groups, derives CAVLC nC through persistent picture-relative neighbour context, records uncoded blocks as TotalCoeff=0, and validates picture bounds. The same reader now consumes 4:2:0 and 4:2:2 chroma DC blocks using their dedicated 4-/8-coefficient CAVLC tables, followed by the component-specific 15-coefficient AC blocks when coded-block-pattern-chroma is 2. Chroma AC uses independent picture-relative Cb and Cr neighbour contexts on the 2x2 or 2x4 chroma block grids; absent AC blocks are recorded as zero TotalCoeff. Synthetic tests cover coded/uncoded groups, Intra16x16 DC-before-AC ordering, luma block order, 4:2:0/4:2:2 chroma DC/AC layouts, independent component contexts, unsupported 4:4:4/separate-colour-plane/field cases and invalid coordinates/patterns. The residual reader is a macroblock-level component; the slice decoder now supplies raster traversal and QP management. CABAC and B/SP/SI macroblock syntax remain unsupported.
- A 4x4 luma residual reconstruction helper now connects the existing CAVLC block model, zigzag-to-raster scan conversion, SPS/PPS scaling-matrix-aware inverse quantisation, the 4x4 inverse integer transform and prediction-plus-residual clipping. It supports full 16-coefficient Intra4x4 blocks and the 15-coefficient AC portion of Intra16x16 blocks; Intra16x16 DC transform/dequantisation is deliberately separate and remains to be implemented before complete Intra16x16 reconstruction.
- Luma intra prediction now has reusable H.264 Intra4x4 predictors for all nine modes (vertical, horizontal, DC and six directional modes), and Intra16x16 predictors for vertical, horizontal, DC and plane modes. The API requires the caller to provide reference samples and explicit availability flags so picture/slice boundaries and constrained-intra rules remain controlled by macroblock traversal. The current luma intra prediction APIs operate on 8-bit samples; separate sample-domain residual-addition helpers clip 8-bit and 8–14-bit high-bit-depth reconstructed samples. Focused tests cover reference availability, DC edge cases, all prediction modes, plane prediction, clipping and validation. Intra16x16 luma DC reconstruction is implemented separately. Chroma intra prediction now implements DC, horizontal, vertical and plane modes for 4:2:0 (8x8) and 4:2:2 (8x16), including per-4x4 DC regions, edge availability and format-specific plane gradients. Chroma residual reconstruction supports the corresponding 4:2:0 and 4:2:2 layouts. Intra4x4 and Intra8x8 luma prediction are integrated into I_NxN macroblock reconstruction. All sixteen 4x4 blocks or four 8x8 blocks are resolved using picture-relative mode state, reconstructed in normative order, and committed with the corresponding 4:2:0/4:2:2 chroma prediction and residual planes. The 8x8 CAVLC path assembles four interleaved 4x4 coefficient lists into the normative 64-level scan sequence and gathers filtered references, including above-right samples. I_16x16 and I_PCM reconstruction record DC prediction modes for neighbouring blocks. High-bit-depth prediction, inter-slice decoding and final picture scheduling remain outstanding.
- Intra4x4 and Intra8x8 I_NxN luma reconstruction are now integrated with chroma prediction/residual reconstruction and decoded-picture surface commits. Intra8x8 CAVLC residual parsing decodes the four 4x4 coefficient lists for each coded 8x8 block and interleaves their scan levels into the normative 64-coefficient 8x8 scan sequence. The luma reconstructor processes four blocks in decoding order, gathers filtered top/left/top-left references including above-right macroblock samples, resolves picture-relative 8x8 modes and applies the existing 8x8 inverse quantisation/transform path. Intra4x4 macroblocks publish their corresponding top-left 4x4 modes to the 8x8 neighbour context; I_16x16 and I_PCM macroblocks publish DC mode 2. I_PCM parsing validates byte-alignment zero bits and reads raw 8-bit Y/Cb/Cr planes for frame-only 4:2:0 and 4:2:2. Focused tests cover CAVLC coefficient interleaving, both chroma formats, external and above-right references, PCM alignment/sample order, surface commits, malformed residuals and unsupported syntax.
- An Intra8x8 luma prediction primitive now implements all nine prediction modes, including filtered top/left/top-left reference samples, top-right edge extension, DC edge cases and the transposed directional modes. Focused tests cover all modes, filtering, top-right availability, reference requirements and invalid inputs. This primitive is now integrated into Intra8x8 macroblock reconstruction with CAVLC residual parsing, reference gathering and decoded-picture surface commits.
- An Intra8x8 luma residual reconstruction primitive now accepts a complete 64-coefficient scan-order block, maps zig-zag or field scan to raster order, applies the existing 8x8 inverse quantiser and inverse transform, and adds/clips the residual against 8-bit prediction samples. Focused tests cover zero residual, DC reconstruction, clipping, scan ordering, parameter-set validation, transform enablement and invalid inputs. CAVLC 8x8 coefficient parsing, coded-block-pattern integration, macroblock placement and surface commit are now implemented for frame-only 8-bit 4:2:0/4:2:2.
- I_PCM macroblock parsing and reconstruction now consumes validated zero alignment bits and raw 8-bit Y/Cb/Cr samples for frame-only 4:2:0 and 4:2:2 pictures. PCM macroblocks are committed as intra-coded surface regions and seed DC neighbour prediction modes.
- A decoded-picture surface now stores reconstructed 8-bit Y, Cb and Cr planes for frame-only 4:2:0 and 4:2:2 pictures, with per-macroblock decoded/slice/intra availability metadata. An intra reference provider gathers luma 16x16 and chroma 8x8/8x16 top, left and top-left samples while enforcing picture edges, slice boundaries and constrained-intra availability. The macroblock reconstruction orchestrator connects I_16x16, Intra4x4 I_NxN, Intra8x8 I_NxN and I_PCM reconstruction with chroma prediction/residual reconstruction where applicable, then commits all three planes to the picture surface. I_16x16 and I_PCM reconstruction record DC prediction modes for adjacent intra blocks; picture mode contexts can be reset explicitly. Synthetic tests cover plane geometry, sample storage, reference gathering, slice-edge availability, both chroma formats, all supported intra macroblock types, external/above-right references and unsupported syntax. Inter macroblocks, inter-slice decoding and picture scheduling remain outstanding.

- Parsed P-slice inter macroblock syntax is now connected to picture-relative motion-vector prediction. A reconstruction adapter maps the five supported list-0 macroblock shapes into the 4x4-block motion-vector grid, resolves each partition in syntax order, adds MVD values, clips vectors, and makes earlier partitions immediately available to later partitions. It validates active RefPicList0 indices, partition geometry, complete sub-partition coverage and malformed MVD payloads before changing picture state. P_Skip's special zero-vector condition and ordinary 16x16 predictor path are also implemented. This remains motion-vector reconstruction only: reference-picture sample interpolation, weighted prediction, residual reconstruction for inter macroblocks and final inter pixel compensation are not yet implemented.

- H.264 uni-directional weighted prediction is now implemented for list-0 8-bit 4:2:0/4:2:2 prediction blocks. The weighting stage applies the per-reference luma and Cb/Cr weights and offsets from the parsed slice prediction-weight table, uses the normative denominator rounding and default weights when component flags are absent, clips results to 8-bit samples, validates table/plane dimensions, and preserves the original prediction buffers. The P inter-macroblock prediction adapter accepts the parsed weight table and applies the selected reference's weights after motion compensation, including the P_Skip adapter. Focused tests cover explicit/default weights, independent chroma components, reference-index selection, rounding, clipping, malformed tables, unsupported formats and end-to-end adapter integration. This is uni-prediction only; B-slice bi-prediction and implicit weighted bi-prediction remain outstanding.\n- H.264 list-0 motion compensation now generates prediction blocks from reconstructed 8-bit reference surfaces. Luma interpolation implements integer, horizontal/vertical/diagonal half-sample positions using the six-tap `[1, -5, 20, 20, -5, 1]` filter, followed by quarter-sample averaging and 8-bit clipping. Chroma interpolation uses bilinear eighth-sample weighting with the correct horizontal and 4:2:0/4:2:2 vertical subsampling scales. Out-of-frame reference coordinates use edge replication. A P inter-macroblock prediction adapter now connects parsed inter syntax, reconstructed partition motion vectors, active RefPicList0 selection and per-partition Y/Cb/Cr prediction; P_Skip prediction uses RefPicList0[0]. Synthetic tests cover filter impulse responses, fractional positions, negative coordinates, edge extension, both supported chroma formats, active reference selection and skipped macroblocks. This stage produces prediction buffers only: it does not yet decode inter residuals, apply weighted prediction, combine prediction with residuals, write completed inter macroblocks into the current picture surface, or traverse an entire P slice. B-slice/bi-prediction and DPB lifecycle remain outstanding.

The roadmap is complete only when the implemented feature set is backed by automated tests and real H.264 streams with independently verified decoded output.
