# H.264 / AVC decoder roadmap

PixoraStudio is implementing a managed H.264/AVC decoder in `PixoraStudio.MediaEngine`. The target is native decoding without FFmpeg or LibVLC in the decoding path. Those tools may be used externally to create reference test streams, but are not runtime decoder dependencies.

## Decoder scope and support policy

The roadmap targets a standards-based decoder with explicit profile/tool capability checks. H.264 is not a single fixed bitstream format: profiles, chroma formats, bit depths, entropy modes, interlace modes and optional tools vary substantially. A stream must be rejected with a clear unsupported-feature error whenever its syntax or decoding tools are not implemented. It must never be silently rendered as if correctly decoded.

## Implementation stages

1. **Bitstream foundation** — Annex B and MP4 length-prefixed NAL framing, EBSP/RBSP conversion, bit reading and Exp-Golomb primitives. Initial SPS/PPS parsing is in place.
2. **Parameter sets and picture syntax** — complete SPS/PPS including VUI/HRD, slice-group syntax, slice headers, picture-order-count derivation and reference-list modification.
3. **Baseline profile reconstruction** — CAVLC residual parsing, inverse scans/transforms/dequantisation, intra prediction, macroblock reconstruction and decoded-picture-buffer management.
4. **Inter prediction** — P/B slice syntax, reference picture lists, motion-vector prediction, sub-pixel interpolation, weighted prediction and motion compensation.
5. **Additional profiles/tools** — CABAC, Main/High profile transforms and prediction tools, field coding and supported chroma/bit-depth variants. Each tool is gated by conformance tests.
6. **Output and container integration** — cropped YUV picture surfaces, colour conversion, MP4 sample/decode-order scheduling, POC reordering, seeking and synchronisation with the existing AAC playback path.
7. **Compatibility and hardening** — real-stream test corpus, malformed/truncated bitstreams, resource limits, cancellation and regression/performance tests.

## Current implementation status

- NAL framing, EBSP-to-RBSP conversion, bit reader and initial SPS/PPS readers are implemented.
- SPS parsing now reads VUI aspect ratio, overscan, video signal/colour description, chroma location, timing, NAL/VCL HRD, picture-structure and bitstream-restriction metadata.
- VUI/HRD parsing is covered by focused synthetic unit tests.
- PPS parsing now covers reference defaults, weighted prediction, QP offsets, deblocking/constrained-intra/redundant-picture flags, all FMO map syntax types (0–6), and the optional transform/scaling-matrix extension. The SPS is accepted as an optional context when PPS scaling-list count depends on chroma format.
- Slice-header parsing is implemented for ordinary non-IDR and IDR slice NAL units, covering I/P/B/SP/SI slice types, frame/field syntax, POC types 0/1/2, reference-count overrides, reference-list modifications, weighted prediction tables, decoded-reference marking/MMCO, CABAC initialisation syntax, QP/deblocking syntax and FMO slice-group change cycles.
- A stateful POC calculator now derives top-field, bottom-field and picture order counts for POC types 0, 1 and 2, including LSB wraparound, frame-number wraparound, reference/non-reference pictures, field pictures, IDR resets and MMCO 5 state resets. It must be called once per primary coded picture.
- SPS now retains the frame-number gap flag, MBAFF flag and POC type 1 offset-cycle values needed by picture-order derivation.
- Focused synthetic slice-header tests cover IDR/I, P with list modification and MMCO, B weighted prediction, POC type 1 field pictures, SP/CABAC and FMO cycle parsing.
- CAVLC VLC tables are implemented for context-selected coeff_token, separate 4:2:0 and 4:2:2 chroma-DC coeff_token, total_zeros and run_before. Residual-block decoding assembles trailing-one signs, coefficient levels (including level-prefix escape handling), total_zeros and run_before into forward scan-order coefficient arrays. 4x4 zigzag/field and 8x8 zigzag/field scan conversion are implemented. The 4x4 and 8x8 inverse integer transforms and 2x2 chroma-DC Hadamard transform are implemented with focused tests. A 4x4 inverse quantiser now applies the three H.264 position classes, QP quotient/remainder scaling and raster-order scaling lists; slice luma QP derivation includes the SPS bit-depth offset and range checks. SPS/PPS scaling-list syntax is retained, including use-default markers, and the scaling-matrix resolver applies normative defaults, list inheritance, SPS-to-PPS fallback and raster-order conversion for both 4x4 and 8x8 matrices. The 8x8 resolver supports the two lists used by 4:2:0/4:2:2 and all six lists for 4:4:4. The 8x8 inverse quantiser applies the six normative coefficient position classes, QP quotient/remainder scaling and resolved raster-order matrices. Both quantisers can consume effective SPS/PPS matrices directly. Initial I_16x16 macroblock reconstruction is now implemented; complete I_NxN orchestration and slice-data traversal remain outstanding.
- Slice-aware CAVLC neighbour-context state now tracks decoded 4x4 block TotalCoeff values, derives nC from available left/top neighbours using the normative rounded average, and treats picture edges, undecoded neighbours and neighbours in another slice as unavailable. Its wrapper decodes ordinary 15/16-coefficient blocks and records TotalCoeff for later blocks; chroma DC blocks continue to use their dedicated VLC context. Focused tests cover neighbour availability, averaging, slice boundaries, reset, validation and residual-reader integration. The caller must supply picture-relative 4x4 block coordinates in decoding order. Full macroblock syntax and slice-data traversal are not yet implemented.
- An initial I/P macroblock-header prefix reader now decodes I_NxN, I_16x16 and I_PCM type codes, classifies P-slice inter/intra macroblock types, and reads P-slice `mb_skip_run` values with picture-boundary checks. Intra syntax parsing now reads the sixteen 4x4 or four 8x8 `prev_intra*_pred_mode_flag` / `rem_intra*_pred_mode` entries, applies normative remainder-mode remapping when a neighbour-derived predicted mode is supplied, parses chroma prediction mode, maps intra coded-block-pattern values through Table 9-4, and reads `mb_qp_delta` when required (including the I_16x16 exception). The syntax reader supports monochrome, 4:2:0, 4:2:2 and separate-colour-plane handling at this layer. Neighbour-derived Intra4x4 prediction-mode lookup is now implemented as picture-relative state: it applies the DC-mode fallback for unavailable neighbours, takes the minimum of available left/top modes, respects slice boundaries and resolves/stores parsed prev-mode/remainder entries. Slice-aware neighbour-derived prediction-mode contexts now cover both Intra4x4 and Intra8x8 luma blocks. Each context uses picture-relative block coordinates, applies DC mode 2 whenever either neighbour is unavailable, takes the minimum when both are available, respects slice boundaries and resolves/stores parsed prev-mode/remainder entries. A macroblock-level residual payload reader consumes frame-only I_NxN 4x4 luma residual blocks and I_16x16 luma DC plus optional 15-coefficient AC blocks. It follows the H.264 4x4 macroblock block-scan order, checks coded-block-pattern groups, derives CAVLC nC through persistent picture-relative neighbour context, records uncoded blocks as TotalCoeff=0, and validates picture bounds. The same reader now consumes 4:2:0 and 4:2:2 chroma DC blocks using their dedicated 4-/8-coefficient CAVLC tables, followed by the component-specific 15-coefficient AC blocks when coded-block-pattern-chroma is 2. Chroma AC uses independent picture-relative Cb and Cr neighbour contexts on the 2x2 or 2x4 chroma block grids; absent AC blocks are recorded as zero TotalCoeff. Synthetic tests cover coded/uncoded groups, Intra16x16 DC-before-AC ordering, luma block order, 4:2:0/4:2:2 chroma DC/AC layouts, independent component contexts, unsupported 4:4:4/separate-colour-plane/8x8/field cases and invalid coordinates/patterns. The reader does not yet constitute full slice-data traversal or macroblock reconstruction. CABAC and B/SP/SI macroblock syntax are explicitly unsupported by these readers.
- A 4x4 luma residual reconstruction helper now connects the existing CAVLC block model, zigzag-to-raster scan conversion, SPS/PPS scaling-matrix-aware inverse quantisation, the 4x4 inverse integer transform and prediction-plus-residual clipping. It supports full 16-coefficient Intra4x4 blocks and the 15-coefficient AC portion of Intra16x16 blocks; Intra16x16 DC transform/dequantisation is deliberately separate and remains to be implemented before complete Intra16x16 reconstruction.
- Luma intra prediction now has reusable H.264 Intra4x4 predictors for all nine modes (vertical, horizontal, DC and six directional modes), and Intra16x16 predictors for vertical, horizontal, DC and plane modes. The API requires the caller to provide reference samples and explicit availability flags so picture/slice boundaries and constrained-intra rules remain controlled by macroblock traversal. The current luma intra prediction APIs operate on 8-bit samples; separate sample-domain residual-addition helpers clip 8-bit and 8–14-bit high-bit-depth reconstructed samples. Focused tests cover reference availability, DC edge cases, all prediction modes, plane prediction, clipping and validation. Intra16x16 luma DC reconstruction is implemented separately. Chroma intra prediction now implements DC, horizontal, vertical and plane modes for 4:2:0 (8x8) and 4:2:2 (8x16), including per-4x4 DC regions, edge availability and format-specific plane gradients. Chroma residual reconstruction supports the corresponding 4:2:0 and 4:2:2 layouts. The 4x4 luma predictor remains a reusable primitive pending I_NxN macroblock orchestration. The 16x16 luma and chroma predictors are now integrated into the initial I_16x16 reconstruction path; high-bit-depth prediction, complete slice traversal and final picture scheduling remain outstanding.
- An initial I_NxN Intra4x4 luma macroblock reconstruction stage now resolves each of the sixteen parsed prediction-mode entries against picture-relative neighbour mode state, processes blocks in normative macroblock decoding order, exposes already reconstructed internal top/left/top-left samples to subsequent blocks, applies 4x4 inverse quantisation/transforms and clips prediction-plus-residual samples. It validates the full residual grid, coefficient counts, unsupported transform-size syntax, PPS/SPS association and unavailable directional references. This is currently a luma reconstruction component, not yet a complete I_NxN macroblock commit: chroma integration, shared mode-context updates for I_16x16 neighbours, Intra8x8 prediction/residual reconstruction and end-to-end tests remain outstanding. Focused tests cover all-sixteen-block reconstruction, internal sample propagation, missing references and malformed payloads.
- A decoded-picture surface now stores reconstructed 8-bit Y, Cb and Cr planes for frame-only 4:2:0 and 4:2:2 pictures, with per-macroblock decoded/slice/intra availability metadata. An intra reference provider gathers luma 16x16 and chroma 8x8/8x16 top, left and top-left samples while enforcing picture edges, slice boundaries and constrained-intra availability. An initial macroblock reconstruction orchestrator now connects I_16x16 luma prediction, Intra16x16 DC/AC reconstruction, chroma DC/horizontal/vertical/plane prediction and chroma residual reconstruction, then commits all three planes to the picture surface. Synthetic tests cover plane geometry, sample storage, reference gathering, slice-edge availability, both chroma formats, full I_16x16 macroblock reconstruction and unsupported syntax. The orchestrator currently supports coded I_16x16 macroblocks only; I_NxN orchestration, slice-data traversal, inter macroblocks and picture scheduling remain outstanding.

The roadmap is complete only when the implemented feature set is backed by automated tests and real H.264 streams with independently verified decoded output.
